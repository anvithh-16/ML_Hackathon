# PathSnap — GPS map matching and route reconstruction

UE24CS352A Machine Learning hackathon. Given a noisy GPS track and the local road network of a trip,
PathSnap predicts the road segment (arc) for every GPS observation and reconstructs a connected route:

```
raw trip files -> per-trip UTM projection -> route-to-GPS label alignment -> candidate arcs (50 m + fallback)
  -> 15 shared features -> 5 classifiers (LogReg, KNN, Decision Tree, Random Forest, XGBoost)
  -> selected model (+ Optuna TPE tuning) -> HMM / Viterbi -> FastAPI (Laptop 1) -> Streamlit + Folium UI (Laptop 2)
```

## 1. Install (macOS, Python 3.10-3.12; also tested on 3.14)
```bash
git clone https://github.com/anvithh-16/ML_Hackathon.git && cd ML_Hackathon
python3 -m venv .venv && source .venv/bin/activate
python -m pip install --upgrade pip && pip install -r requirements.txt
python -c "import xgboost, sklearn, optuna, pyproj, folium; print('ok')"   # if xgboost fails: brew install libomp
```

## 2. Data (not committed)
Copy the organiser dataset unchanged:
```bash
mkdir -p data/raw && cp -R "/path/to/Student folder" data/raw/
ls "data/raw/Student folder/train" | wc -l          # 80
ls "data/raw/Student folder/student_test" | wc -l   # 10
```
Evaluator trips (demo only) go in `data/eval/<trip_id>/`.

## 3. Reproduce everything
```bash
python -m pytest -q                                              # unit + integration tests
python -m src.data.validate                                      # results/eda/*.csv
python -m src.data.make_folds                                    # configs/folds.json
python -m src.features.build_features --partition train          # labels, candidates, features
python -m src.features.build_features --partition student_test
python -m src.labels.check_alignment                             # label sanity checks + maps
python -m src.candidates.generate --sweep                        # radius sweep (train)
python -m eda.eda_plots && python -m eda.eda_maps                # EDA figures + Folium maps
for m in logreg knn dtree rforest xgb; do python -m src.eval.cv_runner --model $m --variant default --dump-scores; done
python -m src.eval.compare_models                                # results/model_comparison.csv + figures
python -m src.tuning.optuna_search --model <selected> --n-trials 40
python -m src.eval.cv_runner --model <selected> --variant tuned --params results/tuning/<selected>_best_params.json --dump-scores
python -m src.hmm.tune_decoder --scores <selected>__tuned --n-trips 20
python -m src.eval.compare_hmm --models <selected>__tuned
python -m src.export.export_artifacts --model <selected> --variant tuned --reason "<why>"
```

| `docs/` | report sections, deployment, AI-use disclosure | all |

## 6. Data-use rules we follow
Group-aware CV on the 80 training trips; student_test only for development comparison; evaluator trips only
read by the API at demo time; ground truth only inside `api/scorer.py`; no hardcoded outputs.
AI assistance is disclosed in `docs/AI_USE_DISCLOSURE.md`.
